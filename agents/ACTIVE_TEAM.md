# Active Agent Team

Status is a registry state, not runtime provisioning. No agent in this repository is an unrestricted autonomous process, and no credentials or production tools are enabled by these definitions.

## Active — recommended first operating team

Eligible for governed workflow implementation once its schema, tool adapter, deterministic policy, audit, tests, and runtime identity exist:

1. `chief-orchestrator` — Chief Orchestrator Agent
2. `data-anomaly-analyst` — Data and Anomaly Analyst Agent
3. `operational-incident-investigator` — Operational Incident Investigator Agent
4. `seo-strategist` — SEO Strategist Agent
5. `engineering-planner` — Engineering Planner Agent
6. `codex-engineering-executor` — Codex Engineering Executor
7. `codex-content-executor` — Codex SEO and Content Executor
8. `qa-verification` — QA and Verification Agent
9. `outcome-learning` — Outcome and Learning Agent
10. `executive-briefing` — Executive Briefing and Notification Agent

## Staged — fully defined, dispatch disabled

- `content-brand` — remains staged until the approved hotel fact base, Quiet Ledger rules, bilingual review, content schemas, and editorial approval workflow are ready.
- `release-deployment` — remains staged until protected environments, authenticated approval, artifact verification, smoke tests, rollback, kill switches, and deployment audit are implemented and independently reviewed.

## Inactive — optional phase two

- `revenue-proposal`
- `b2b-growth`
- `aeo-research`

## Activation gate

Changing `staged` or `inactive` to `active` requires an approved governance task, machine-readable input/output schemas, least-privilege tool credentials, deterministic permission tests, failure/stop tests, independent specialist review, recorded evidence, and an initial Tier 0/shadow-mode playbook. Activation never grants production authority by itself.
