# Glossary

| Term | Meaning |
| --- | --- |
| AI OS | The governed Hotel Commercial Operating System described by the canonical architecture. |
| Compatibility baseline | Read-only snapshot of the finalized platform used for interface discovery and integration planning. |
| Task packet | Approved, bounded work instruction containing scope, risk, commands, checks, evidence, and rollback expectations. |
| Deterministic check | Repeatable non-model validation such as schema validation, lint, typecheck, test, build, or policy evaluation. |
| Independent review | A reviewer or verifier distinct from the implementer assesses scope, checks, and evidence. |
| Evidence | Durable record supporting a claim, decision, verification result, or outcome. |
| Playbook | Versioned automation definition with trigger, evidence requirements, policy, tools, checks, and rollback rules. |
| Policy engine | Deterministic service that authorizes or blocks actions; it cannot be overridden by an AI model. |
| Tier 0 | Observe, analyze, recommend, or draft; no production alteration. |
| Tier 1 | Narrow, reversible, validated low-risk action after proven reliability. |
| Tier 2 | Preparation allowed; human approval required before activation. |
| Tier 3 | Prohibited or specialist-only action. |
| Terra | Ordinary implementation model and default executor for bounded engineering work. |
| Luna | Model for bounded discovery, summarization, inventory, and routine preparation. |
| Sol | Escalation model for architecture, security, payment, concurrency, RLS, and difficult decisions. |
| Local Qwen | Untrusted offline preprocessing assistant; its output is not evidence and must be verified. |
